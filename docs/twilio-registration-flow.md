# Twilio Voice SDK Registration Flow

## Overview
This document explains **how the Twilio Voice JavaScript SDK registers a browser client** and **how Twilio knows which browser/device belongs to a particular agent** (e.g. `AG_001`).

---

## 1. Backend token generation
1. The frontend requests a token: `GET /api/v1/telephony/twilio/token?agentId=AG_001`.
2. `TelephonyService.generateToken()` creates a **VoiceGrant**:
   * `incomingAllow = true` – allows PSTN → browser calls.
   * `outgoingApplicationSid` points to the TwiML App that will be used for outbound calls.
3. An **AccessToken** (JWT) is built with the Twilio Account SID, API Key SID/Secret and the **identity claim** set to the agent ID (`AG_001`).
4. The JWT is returned to the browser together with the `identity` field.

---

## 2. Browser SDK initialization
```ts
const res = await http.get<TelephonyToken>(
   `${GATEWAY_URL}/api/v1/telephony/twilio/token?agentId=${agentId}`
).toPromise();

this.device = new Device(res.token, {
  logLevel: 'debug',
  edge: 'ashburn'
});
await this.device.register();
```
* `new Device(res.token, …)` **creates** the SDK instance but does **not** open any network connection yet.
* `device.register()` performs the **real registration**:
  1. Opens a **WebSocket** to `voice-js.twilio.com` (the Twilio signalling gateway).
  2. Sends the JWT in the opening handshake.
  3. Twilio validates the token signature and extracts the `identity` claim (`AG_001`).
  4. Twilio creates an **identity‑to‑WebSocket mapping** in its internal registry.
  5. The SDK receives a `registered` event.

---

## 3. Heartbeat & liveness
* After registration, the SDK automatically sends a **heartbeat frame** (a small ping) **every few seconds** over the same WebSocket.
* Twilio monitors these heartbeats:
  * If they **stop** (e.g., the page is closed, network drops, or the token expires), Twilio **removes** the identity mapping.
  * The agent is then considered **offline** and will not receive further inbound calls.

---

## 4. How Twilio decides which browser receives a call
1. When a PSTN call is matched to an agent, Mini‑Genesys’s routing service publishes a `routing‑events` message that contains:
   ```json
   { "status": "ASSIGNED", "agentId": "AG_001", "callId": "CALL_42" }
   ```
2. The Telephony Service consumes the event and stores `assignedAgentId = AG_001` in the `TelephonyCallSession` row.
3. The next time Twilio executes the **bridge TwiML** (generated by `TelephonyService.getBridgeTwiml`), it returns:
   ```xml
   <Response>
     <Dial answerOnBridge="true">
       <Client>AG_001</Client>
     </Dial>
   </Response>
   ```
4. The `<Client>` element tells Twilio’s media server to **look up the active registration for identity `AG_001`**.
5. Because the browser SDK previously registered that identity, Twilio knows **exactly which WebSocket (and therefore which browser instance)** to push the inbound media to.
6. Twilio then completes the WebRTC handshake (SDP‑offer/answer, ICE) and streams audio between the PSTN leg and the agent’s browser.

---

## 5. What happens if the registration is missing?
* If the identity mapping does not exist (e.g., the agent’s browser never called `register()` or it timed‑out), Twilio cannot find a destination for `<Client>AG_001</Client>`.
* Twilio will respond with a **`404 Not Found`** error to the bridge request, and the caller will hear the “still in queue” TwiML until the agent comes back online and registers again.

---

## 6. Key take‑aways
| Step | Who does it? | Purpose |
|------|--------------|---------|
| Token request | Front‑end (Angular) → Backend | Obtain a short‑lived JWT containing the agent’s identity. |
| Device construction | Front‑end | Create the SDK instance with the JWT. |
| `device.register()` | Front‑end SDK | Open WebSocket, authenticate, bind identity, start heartbeat. |
| Heartbeat | SDK (every few seconds) | Keep the registration alive; loss => agent becomes unavailable. |
| Routing event | Routing Service → Kafka → Telephony Service | Assign an agent (`AG_001`) to a call and store it in DB. |
| Bridge TwiML (`<Client>AG_001</Client>`) | Telephony Service → Twilio | Tell Twilio which registered identity to send media to. |

```
Customer ─► Twilio (PSTN) ─► TwiML App ─► /bridge?callSid=…
                                   │
                                   ▼
          Backend generates JWT (identity=AG_001) ─► Front‑end
                                   │
                                   ▼
          Browser SDK: new Device(token) ─► device.register()
                                   │  (opens WS to voice‑js.twilio.com)
                                   ▼
          Twilio registers identity ↔ WebSocket connection (heartbeat)
                                   │
                                   ▼
          Bridge TwiML contains <Client>AG_001</Client>
                                   │
                                   ▼
          Twilio looks up registration → streams media → Browser
```
